# v1.3.0

发布日期：2026-10-24

这个版本修掉了一个很隐蔽的遥控器操作问题，并把构建与文档整理成可长期维护的形态。

## 亮点

- **遥控器能选中「白名单 / 清理记录」了** —— 之前这一行会被焦点搜索整段跳过
- 版本号改为语义化三段式，构建产物带版本号，便于分发和回溯
- 完整补齐开源项目的文档体系

## 修复

### 遥控器无法选中「白名单 / 清理记录」

主界面把「白名单」和「清理记录」并排放置以节省一行高度，结果按下键时焦点从
「关闭自动清理」**直接跳到「清理范围」**，中间这行完全选不中。

根因不在布局，在 `FocusFinder` 的候选打分：

```
13 × 纵向距离² + 横向偏移²
```

| 候选 | 纵向距离 | 横向偏移 | 加权距离 |
| --- | --- | --- | --- |
| 白名单（左半，中心 x=525） | 11px | 435px | 190798 |
| 清理范围（整宽，中心 x=960） | 108px | 0 | **151632** ← 胜出 |

纵向近 10 倍，仍然输在横向偏移被平方放大。`uiautomator dump` 证实两个按钮
本来就是 `focusable="true" clickable="true"`——能聚焦，只是焦点搜索没选它们。

修复方式是用 `setNextFocusUpId/DownId/LeftId/RightId` 显式指定焦点链，
不再依赖几何搜索。列表页右上角的「恢复默认 / 清空记录」按钮也一并补上了上下焦点。

验证结果（读取 `focused="true"` 节点，比截图判断可靠）：

```
关闭自动清理 → ↓ 白名单 → ↓ 清理范围 → ↑ 白名单 → ↑ 关闭自动清理
白名单 ↔ 清理记录 左右互通，两个页面均可正常打开
```

## 变更

- 版本号 `1.3` → `1.3.0`，`versionCode` `4` → `10300`
- `build.sh` 从 `AndroidManifest.xml` 读取版本号作为唯一来源
- 产物改为 `build/memclean-<version>.apk`，另保留 `build/memclean.apk` 供脚本引用
- `build.sh` 支持 `KEYSTORE` / `KS_PASS` / `KEY_ALIAS` / `KEY_PASS` 签名正式包
- `build.sh` 在未显式指定 SDK 时回落到 `ANDROID_SDK_ROOT` / `ANDROID_HOME`，便于 CI 复用
- 新增 `CHANGELOG.md`、`CONTRIBUTING.md`、`Makefile`、`.editorconfig`、Issue/PR 模板

## 升级说明

从 1.2.0 覆盖安装即可，**白名单、清理记录、统计都会保留**（签名未变）。

```bash
adb install -r memclean-1.3.0.apk
```

如果之前没授权过，仍需：

```bash
adb shell appops set com.mibox3.memclean GET_USAGE_STATS allow
```

## 下载

Release 附件：

| 文件 | 说明 |
| --- | --- |
| `memclean-1.3.0.apk` | 安装包，约 45 KB |
| `SHA256SUMS.txt` | 校验和，由 CI 在构建后生成 |

校验：

```bash
shasum -a 256 memclean-1.3.0.apk   # macOS
sha256sum memclean-1.3.0.apk       # Linux
```

> 同一个 commit 重复构建出的 APK 二进制并不完全一致（zip 内文件时间戳不同），
> 所以校验和**以附件里的 `SHA256SUMS.txt` 为准**，不要照抄文档里的值。

> 这个包用自动生成的调试证书签名。自行编译时可用 `KEYSTORE=... ./build.sh`
> 换成自己的证书，但换了证书就无法覆盖安装，需要先卸载。

## 已知问题

- Android 8.0+ 未适配（需要前台服务）
- 清理是无差别的，后台放歌/下载会被中断，需加白名单
- 清理记录最多 200 条，不支持导出
